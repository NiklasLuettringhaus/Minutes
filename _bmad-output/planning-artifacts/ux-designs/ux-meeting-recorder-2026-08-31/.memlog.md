- (event by coach) Headless create. Sources by reference: prd.md (48 FRs, §10 Information Architecture, §10.3 checklist row anatomy), prd addendum §2 (FluidVoice reference table), brief addendum (platform constraints). Not duplicated into the spines.
- (decision by user) User-supplied visual reference (screenshot, mid-run): FluidVoice. Directive: 'I like the way fluid voice sets up the models. Do something similar.' Observed: grouped sidebar; Quick Setup checklist rows with state icon + title + one-line why + right-aligned Done pill or action button; completed rows de-emphasised; Run Onboarding Again; Test Playground card; single teal accent on off-white with recessed cards.
- (decision by coach) DESIGN.md inherits from Apple HIG / SwiftUI semantic colours rather than inventing a palette, using the spec's 'note' field convention for platform-owned values. Rationale: a native menu bar utility that invents its own greys and type ramp looks wrong on macOS and costs maintenance for nothing (PRD SM-C2). Literal hex is specified ONLY where semantics demand a specific colour the system does not provide.
- (decision by coach) Three literal colours only: Recording red, Transcribing amber, and a teal brand accent carried over from the reference. Red for Recording follows universal convention and macOS's own capture indicator; teal was chosen because the user liked it AND because it cannot be confused with the Recording state, which a warm accent would.
- (decision by coach) Form factor resolved: two surfaces only — a menu bar item (many times a day) and one sidebar window (rarely). Locked by PRD §10.1; a third surface is a scope violation.
- (assumption by coach) Icon glyph set assumed: waveform family for Idle, filled record dot for Recording, and a progress/arrow form for Transcribing. Shape must carry state independently of colour (PRD FR-2, NFR-7) so the set has to differ in silhouette, not just tint.
- (event by coach) Key-screen mock rendered: mockups/getting-started.html — two states of the Getting Started pane (mid-setup light, complete dark) validating the borrowed checklist pattern and the extended Test Playground result card.
- (decision by coach) Mock coverage: Getting Started mocked because it is the surface the user pointed at and layout drives its behaviour. Meetings, Transcription, Detection, General left spine-only — they are stock Form/List panes whose behaviour the EXPERIENCE.md tables fully determine, so a mock would add nothing.
- (event by coach) spines finalized
- (event) Headless -H update, increment 4: voice enrolment (PRD FR-62..FR-65). No new destination and no new pane — one checklist row, one card, one distinguished list entry.
- (decision) The enrolment card IS the Test Playground card, not a new shape. The Playground already taught the user that a countdown + meter + facts-based result means 'the app is about to listen and will then say what it heard'. Enrolment makes that exact promise. Logged as the increment's strongest assumption and the easiest to reverse.
- (decision) One level meter during enrolment, not two. Enrolment never opens the System Stream, so a System meter would be a lie about what is being read. Meter count is information.
- (decision) The enrolment row is row 7, last. Rows never reorder by rule, and renumbering a shipped row to put the newest thing first would disturb a surface the user already knows. Prominence comes from being in the primary checklist at all.
- (change) Corrected a stale table: the rows table listed 5 rows and the shipped pane has had 6 since increment 2 (detection prompts was added as row 5 and never written down). KF-4 step 2 and step 8 corrected with it.
- (change) DESIGN.md gained four components that had already shipped and were never declared: level-meter, fact-chip, voice-row, and the speaker-chip's room variant. The spine was describing a two-place world the product left behind when AD-11 was amended.
- (decision) colors.ink-amber (#9A6203) documented, not introduced — it is the value the in-room chip already ships in. Kept distinct from state-blocked (#B26A00) despite the near-identical hue: that one means 'the machine cannot do this yet', and an in-room voice is not a blocked capability. Two meanings on one value is how a palette stops carrying information.
- (change) New state pattern 'Identity, claimed or refused': four situations, and the rule that a claim states its basis while a refusal renders as ordinary rather than as an error. Dressing an honest refusal as a failure would push the user toward wanting the guess back.
- (change) KF-8 added. Its climax is deliberately dull (25 seconds, two facts, a row going quiet) because everything that matters happens the next morning in a meeting the user is not thinking about the app during.
- (decision) A two-voice enrolment sample is REFUSED, not accepted with a warning. Cost asymmetry: a bad fingerprint is silent and lasts months; a second attempt costs 25 seconds.
- (decision) No rename on the enrolled entry. The display name is owned by 'Your name in transcripts' in the same pane, and two places to edit one name is the defect avoided.
- (assumption) Showing the measured match distance in the meeting detail is this document's reading of FR-65: a number the user cannot set but can check is honesty, not a dial — the same argument as the Playground's throughput figure.

The increment adds no new pane, so no surface exists that needs a visual reference it does not already have.
